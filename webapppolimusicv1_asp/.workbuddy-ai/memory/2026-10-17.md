# 2026-10-17

## PoliMusic — clon de Spotify en ASP Clásico (VBScript)

Se construyó la aplicación completa sobre la base existente `BDD_PoliMusic` (SQL Server).

**Decisiones clave**
- No se crean tablas ni datos: la app solo hace SELECT/INSERT/UPDATE/DELETE sobre
  `TBL_USER` y `TBL_SONG`. Se eliminó el script `sql/BDD_PoliMusic.sql` que se había
  generado al inicio (el usuario aclaró que la BD ya existe).
- Tema azul oscuro propio en `css/style.css` (nada de verde Spotify).
- Consultas parametrizadas con `ADODB.Command`; salida escapada con `H()`.
- `includes/db.asp` prueba MSOLEDBSQL con Encrypt, luego sin Encrypt y por último SQLOLEDB.
- Login tolerante al esquema: si `TBL_USER` no tiene `USER_TYPE`, entra como rol 0 y
  `songs.asp` muestra un aviso (la captura del usuario mostraba la tabla sin esa columna).
- `play.asp` incrementa `PLAYS` vía `fetch` desde `js/app.js` (una vez por reproducción).
- `SongUrl()` acepta rutas relativas, `C:\...`, solo nombre de archivo o URL completa.

**Archivos**
`login.asp`, `logout.asp`, `songs.asp`, `song_add.asp`, `song_edit.asp`,
`song_delete.asp`, `play.asp`, `web.config`, `includes/*` (config, db, auth, layout_top,
layout_bottom, song_form), `css/style.css`, `js/app.js`, `assets/songs/*.wav` (6 pistas
de ejemplo generadas), `tools/` (lint + render de pruebas + generador de audio), `README.md`.

**Verificación**
- `tools/lint_asp.py`: 13 archivos sin problemas de bloques VBScript.
- `tools/render_asp.py` (shim de objetos ASP + cscript + SQL Server): probados login
  correcto/incorrecto, guardas de sesión y rol, CRUD completo, `play.asp` (128→129) y
  escape de XSS.
- Capturas headless de login, listado (admin y usuario), formulario, borrado y móvil.
